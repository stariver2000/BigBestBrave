# 구조 설계

이 문서는 현재 구현과 일치하는 단 하나의 설계 문서다. 코드가 바뀌면 여기도 같은 변경에서 고친다.

## 1. 이 저장소가 만드는 것

하나의 도메인 아래에서 경로만 갈라지는 페이지 트리다.

- 도메인은 고정되고 URL 경로가 트리 좌표가 된다. `/` (1층) → `/design` (2층) → `/design/color` (3층) … 최대 10층.
- 페이지마다 **판매해도 될 품질의 기능 하나**를 갖는다. 노드 정의의 `capability` 필드가 그 약속을 기록하며,
  화면에는 노출하지 않고 테스트(`page-contract`)가 선언을 강제한다.
- 페이지의 외형과 성격은 손으로 칠하지 않고 **특성(trait) 조합에서 기계적으로 파생**된다.
- 여러 페이지가 로컬 LLM 한 대를 공유하므로, 모든 LLM 호출은 동시 실행이 제한된 단일 게이트웨이를 지난다.

## 2. 의존 방향

```
app/ (Next.js 라우트)
  └─> src/shell/      공통 프레임: 히어로, 브레드크럼, 커맨드 팔레트, 언어 전환
        └─> src/looks/            손으로 고른 미감(팔레트·형태·그림자)
        └─> src/modules/<페이지>/  페이지 고유 코드 (한 페이지 = 한 디렉토리)
              └─> src/kit/         어느 주제에서도 쓰는 재사용 부품
                    └─> src/core/  공통 모델: 색, 특성, 트리, i18n
src/llm/   페이지 모듈이 옆에서 호출하는 게이트웨이 (core에 의존하지 않는다)
```

- `src/core`는 어떤 상위 계층도 import하지 않는다. React와 Next도 모른다.
- 모듈끼리는 서로 import하지 않는다. 공유가 필요하면 `src/kit`으로 내린다.
- 각 계층의 공개 API는 그 디렉토리의 `index.ts` 한 곳에서만 나간다.

## 5. 특성 시스템

`src/core/traits/axes/` 아래 10개 그룹에 40개 축이 있고, 축마다 값이 있다 (총 365개).

`identity`(주제·독자·목적·태도), `mood`(분위기·색온도·밝기·채도·긴장·계절·시간),
`form`(레이아웃·밀도·리듬·정렬·그리드·모서리·테두리·입체·질감), `typography`, `motion`,
`interaction`, `voice`, `content`, `system`(렌더·연산 예산·LLM 사용·상태·오프라인), `accessibility`.

페이지 노드는 이 축들에 값을 선언하고(`TraitVector`), `deriveTokens()`가 그것을 CSS 커스텀 프로퍼티로 바꾼다.
선언하지 않은 축은 `AXIS_FALLBACKS`가 메우므로 부분 선언도 완전한 토큰을 만든다.

색 파생에는 두 가지 보증이 있다.

1. **본문색**: 배경에서 멀어지는 방향으로 명도를 훑어, 선언한 대비 기준(APCA Lc)을 처음 만족하는 색을 고른다. 최대 대비를 쓰지 않는 이유는 눈부심 때문이다.
2. **강조색**: 라벨 가독성(Lc ≥ 60)과 배경 대비(Lc ≥ 40)를 만족하는 후보 중 **실제로 낼 수 있는 채도가 가장 높은** 명도를 고른다. sRGB에서 색상마다 최대 채도가 명도에 따라 달라, 명도를 고정하면 청록 같은 색이 회색으로 깎이기 때문이다.

## 5-1. 룩(look) 계층 — 특성이 계산하지 못하는 것

특성 엔진은 "대비 기준을 넘는 색"을 찾을 수는 있어도 "우아한 색"을 고르지는 못한다.
공식 하나로 수백 페이지를 뽑으면 전부 같은 밋밋함으로 수렴한다. 그래서 미감은 계산하지 않고
**손으로 만든 룩을 특성이 고르는** 구조로 둔다.

- 룩은 팔레트·모서리·그림자를 `--bbb-*` 변수로 덮어쓴다. 간격·타입 스케일·모션은 엔진 값을 그대로 쓴다.
- 노드가 `look: 'serene'` 처럼 선언하면 `frameVariables()`가 파생 토큰 위에 룩을 덮는다.
- 덮는 순서는 `src/looks/resolve.ts` 한 곳에만 있고, 화면과 테스트가 같은 함수를 쓴다.
  룩이 손으로 고른 색이라 엔진의 보증을 받지 않기 때문에, 최종 색을 그대로 검사해야 한다.
- 현재 룩 (페이지가 늘 때마다 한 줄씩 는다)
  - `serene` — 부드럽고 우아한 화면. 라일락 지면에 빛무리, 굴린 모서리, 번지는 그림자. (`/color`)
  - `dossier` — 서류철의 화면. 누런 종이 결, 먹빛 활자, 도장 붉은색, 각진 모서리와 어긋난 그림자. (`/`)
  - `cinema` — 불 꺼진 상영관. 따뜻한 어둠, 필름 그레인, 방송 자막의 노란색. (`/subtitle`)
  - `blueprint` — 모눈종이 위의 도면. 차가운 지면에 두 겹 눈금, 신호용 파랑. (`/projection`)
  - `pager` — 1990년대 무선호출기. 어두운 플라스틱과 연둣빛 액정. (`/beeper`)
  - `pulse` — 눈 감은 어둠과 맥박 하나. 모두 둥근 모서리. (`/rhythm`)
  - `garden` — 화분 옆의 조용한 방. 옅은 초록 지면과 전자잉크. (`/thing`)
  - `gallery` — 흰 벽의 전시장. 색은 화면이 아니라 작품이 낸다. (`/mist`)
  - `proof` — 교정지. 차가운 종이에 붉은 교정 부호. (`/chart`)
  - `vault` — 금고 안쪽. 강철빛 어둠에 놋쇠 한 점. 겁주지 않으려고 붉은 기는 한 줄에만 쓴다. (`/checkup`)
  - `bench` — 실험대. 유일하게 **중간 밝기** 지면이다. 상관 행렬의 양과 음이 같은 무게로 읽혀야 하기 때문이다. (`/rulers`)
  - `gauge` — 밤에 켜 둔 계측기. 유일하게 **채도 있는** 지면(짙은 청록)이다. 눈이 좇을 것이 움직이는 커서 하나뿐이어야 해서 나머지를 모두 내렸다. (`/reach`)
  - `signal` — 불 꺼진 방의 계기 하나. 색이라고는 경고등뿐인 무채색이다. 물음이 "지금 이 말을 할 값이 있는가"라서 눈이 먼저 고르지 못하게 했다. (`/window`)
  - `scale` — 장부와 저울. 해내는 정도와 드는 값을 끝까지 맞바꾸는 화면이라 색을 둘만 둔다. (`/nudge`)
  - `hindsight` — 지난 일을 되짚는 저녁의 찬 빛. 남색은 있었던 일에, 산호색은 그러지 않았더라면 있었을 일에. (`/whatif`)
  - `dyad` — 둘이 마주 앉은 저녁의 방. 금빛은 나에게, 연보라는 상대에게. (`/peer`)
  - `atlas` — 접었다 편 종이 지도. 초록은 길 그 자체에, 자홍은 내가 지나온 자취에. (`/route`)
  - `lens` — 렌즈 코팅의 청록빛과 그 너머의 따뜻한 빛. 청록은 AR 쪽에, 호박색은 손에 든 폰 쪽에. (`/reading`)
  - `palm` — 손바닥의 온기. 눈이 보는 것은 장미빛, 손이 쥔 것은 청회색. 장미빛을 쓰는 유일한 룩이다. (`/grip`)
  - `ripple` — 어두운 유리 아래의 떨림. 보이는 것은 보랏빛, 손끝이 알아채는 것은 초록빛. 어두운 지면 위 보랏빛 강조색은 여기뿐이다. (`/soften`)
  - `thread` — 대화창. 다시 물어 풀린 말은 파랑, 끝내 막힌 말은 녹슨 주황. 밝은 지면 위에 이 두 색을 함께 쓰는 것은 여기뿐이다. (`/again`)
  - `margin` — 책의 난외. 건네받은 물음은 자주, 스스로 적은 물음은 초록. 따뜻한 종이 지면에 제목만 세리프로 두는 유일한 룩이다. (`/context`)
  - `quilt` — 서른아홉 조각의 조각보. 내가 정한 칸은 청록, 아무도 안 보는 칸은 산호색. 어두운 지면에 청록과 산호를 함께 쓰는 것은 여기뿐이다. (`/space`)
  - `circle` — 둘러앉은 자리. 맞는 자리는 짙은 청록, 어긋나는 자리는 흙빛 붉은색. 모서리를 가장 넉넉히 굴린 룩이다. (`/repair`)
  - `glow` — 불 꺼진 방의 화면빛. 붙잡는 빛은 차가운 파랑, 놓아 주는 빛은 호박색. 어두운 지면에 차가운 화면빛 파랑을 강조색으로 쓰는 것은 여기뿐이다. (`/moment`)
  - `prism` — 지각 실험실의 흰 벽. 정확히 읽히는 것은 파랑, 눈에 띄는 것은 자홍. 흰 지면 위에 이 두 색을 함께 쓰는 것은 여기뿐이다. (`/channel`)
  - `mirage` — 신기루. 읽어도 되는 것은 청록, 읽으면 안 되는 것은 모래 위 주황. 모래빛 지면은 여기뿐이다. (`/distance`)
  - `veil` — 얇은 장막 뒤의 방. 숨은 것은 연보라, 드러난 것은 복숭아빛. 어두운 지면 위 복숭아빛 강조색은 여기뿐이다. (`/hidden`)
- 룩 CSS가 겨누는 `data-part` 이름은 부품이 실제로 다는 이름과 같아야 한다.
  2025-09-01에 열다섯 룩이 `[data-part='segmented-option']`을 겨누고 있었는데 부품이 다는
  이름은 `segment`였다. 규칙이 오래 죽어 있었고 아무도 몰랐다. 이름을 바꿀 때는
  `grep -rn "data-part" src/looks/`로 모든 룩을 함께 고쳐야 한다.
- 룩은 색·형태·서체만 바꾸는 것이 아니라 부품의 생김새까지 바꾼다.
  규칙은 `src/looks/<룩>/look.css`에 두고, 컴포넌트에 달린 `data-part` 이름표를 겨눈다
  (`[data-look='dossier'] [data-part='panel']`). CSS 모듈의 클래스 이름은 빌드마다 뒤섞이지만
  이름표는 그대로이기 때문이다. 룩마다 파일이 따로라 여러 세션이 같은 파일에서 부딪히지 않는다.
- 룩 변수는 프레임이 아니라 문서 루트(`:root`)에 심는다. html·body의 배경까지 같은 값을 읽어야
  프레임이 닿지 않는 자리에 직전 룩의 색이 남지 않는다.
- 새 룩 추가: `src/looks/<이름>/` 디렉토리를 만들고 `src/looks/index.ts` 표에 한 줄 더한다.

## 6. 트리와 라우팅

- 라우트 파일은 `app/[[...slug]]/page.tsx` 하나뿐이다. 경로 조각을 레지스트리에 물어 노드를 찾고, 그 노드에 등록된 컴포넌트를 그린다.
- 깊이·경로·자식 목록 같은 트리 내부 정보는 화면에 표시하지 않는다. 사용자에게 보이는 것은
  제목·설명·도구·의견란뿐이며, 페이지 사이 이동은 상단 브레드크럼과 커맨드 팔레트(⌘K)가 맡는다.
- **새 페이지를 추가해도 이 라우트 파일은 수정되지 않는다.**
- 로케일은 URL이 아니라 쿠키(`bbb_locale`)에 둔다. 경로는 트리 좌표이므로 언어가 섞이면 한 노드가 여러 주소를 갖게 된다.

### 새 페이지 추가 절차

1. `src/modules/<이름>/` 디렉토리를 만든다. 최소 구성: `config.ts`, `dictionary.ts`, `node.ts`, `ui/`, `index.ts`.
2. `node.ts`에서 `parentId`와 `slug`를 정한다. 부모 노드의 `splitAxis`에 어떤 기준으로 갈라지는지 적는다.
3. `src/modules/index.tsx`의 `PAGE_MODULES` 배열에 한 줄 추가한다.
4. 재사용 가능한 부품이 나오면 `src/kit`으로 올린다.

기존 모듈은 건드리지 않는다. 등록기는 중복 id·중복 경로·잘못된 slug·깊이 초과를 등록 시점에 예외로 잡는다.

## 7. LLM 게이트웨이

- 엔드포인트는 OpenAI 호환 로컬 런타임(Ollama, llama.cpp, vLLM)을 가정하고 `LLM_BASE_URL`로 주입한다.
- `LLM_BASE_URL`이 없으면 LLM 기능 전체가 "사용 불가"로 내려가고, **모든 페이지는 LLM 없이 정상 동작해야 한다.** Chroma Lab의 이름 짓기는 규칙 기반 이름으로 대체된다.
- `ConcurrencyLock`이 FIFO 큐로 동시 실행을 제한한다(기본 1). 대기가 길어지면 기다리던 요청을 먼저 거절해 사용자에게 즉시 알린다.
- 이 락은 **프로세스 내부 범위**다. 서버리스에서 인스턴스가 여러 개 뜨면 인스턴스마다 큐가 생긴다. 전역 직렬화가 필요해지면 외부 저장소 기반 락으로 교체한다.
- 범용 완성 엔드포인트는 공개하지 않는다. 용도별 라우트(`/api/llm/palette-name`)가 서버에서 프롬프트를 조립한다.

### 배포 시 주의

Vercel의 서버리스 함수는 사용자의 로컬 LLM에 접근할 수 없다. 배포 환경에서 `LLM_BASE_URL`을 비워 두면
LLM 기능만 자동으로 꺼지고 나머지는 그대로 동작한다. 나중에 터널이나 호스팅 엔드포인트를 넣으면 켜진다.

## 7-1. 의견란

모든 페이지 하단에 의견란이 붙는다. 여기 쌓인 요구·불만이 다음 업데이트의 입력이 된다.

- 댓글은 페이지 경로(`path`)에 묶여 저장된다. 트리 좌표가 곧 댓글의 소속이라,
  `/`의 의견과 `/color`의 의견은 서로 섞이지 않는다. 트리가 10층으로 갈라져도 같은 규칙이 유지된다.
- 답글은 부모 id로 자료에 남고, 깊이는 `COMMENTS_MAX_DEPTH`(기본 3)까지다.
  한도에 닿은 댓글에는 답글 버튼 자체를 숨긴다. 눌러도 실패할 버튼은 두지 않는다.
- 저장소는 계약(`CommentStore`)과 구현이 분리돼 있다. 로컬은 JSON 파일, 쓰기가 막힌 환경은 메모리.
  파일 저장은 읽기-쓰기 사이가 겹치면 글이 사라지므로 전 과정을 락으로 감싸고, 임시 파일에 쓴 뒤 이름을 바꾼다.
- 이름을 비우면 언어 중립 표식(`anonymous`)으로 저장하고, 화면이 각자의 언어로 번역해 보여 준다.
- 등록되지 않은 경로로 오는 요청은 거절한다. 저장소에 쓰레기가 쌓이는 것을 막기 위함이다.

### 배포 시 주의

서버리스에서는 파일이 유지되지 않는다. 지속 저장이 필요해지면 `CommentStore` 계약을 구현한
외부 저장소 클래스를 추가하고 `COMMENTS_DRIVER`로 고른다. 다른 코드는 손대지 않는다.

## 8. 주제를 고르는 기준

**논문 한 편 = 페이지 한 장.**

페이지의 주제는 국내 대학(KAIST·서울대·POSTECH)의 최근 연구에서 가져온다. 조건은 두 가지다.

1. **실재하는 논문이어야 한다.** 제목·저자·발표처를 확인하고 `config.ts`의 `PAPER`에 남긴다.
   기억에 의존해 인용하지 않는다. 지어낸 인용은 페이지 전체를 거짓으로 만든다.
2. **브라우저 안에서 결정론적으로 돌아가야 한다.** 모델 가중치나 서버가 필요한 연구는
   이 사이트의 조건(연산 예산 0, 로컬 실행)에 맞지 않으므로 고르지 않는다.

논문을 그대로 재현했다고 주장하지 않는다. 무엇을 가져왔는지를 페이지와 코드 주석에 밝힌다.

### 페이지는 스스로 움직여 보인다

도구를 처음 열면 대개 빈 화면과 단추만 있다. 무엇을 넣어야 움직이는지 모르면 사람은 아무것도 하지 않고 나간다.
그래서 페이지가 먼저 움직인다 — 자기가 무엇을 하는 물건인지 스스로 시연하고, 사람이 손을 대면 자리를 비켜 준다.

- `src/kit/autopilot`의 `useAutopilot(steps)`가 단계를 하나씩 실행하고 끝나면 처음으로 돌아간다.
  단계는 페이지가 자기 상태 설정 함수로 짠다. 시계는 훅이 맡고, 차례와 기다림 계산은 `model.ts`에 순수 함수로 있다.
- **사람이 누르거나 자판을 치거나 굴리면 그 즉시 멈춘다.** 시연 중에 조작이 되받아쳐지면
  사람은 자기가 무언가 망가뜨렸다고 느낀다. 멈춘 뒤에는 `AutopilotChip`의 '다시 보여 주기'로 되돌린다.
- 움직임을 줄여 달라고 설정한 사람(`prefers-reduced-motion`)에게는 스스로 시작하지 않는다. 눌러야 시작한다.
- 지금 스스로 도는 페이지: `/subtitle`(예시를 넣고 재생하며 글씨를 키워 원본이 넘치는 장면을 만든다),
  `/beeper`(말을 보내고 되돌아온 말을 보여 준다), `/projection`(진실의 렌즈를 겹쳐 보이는 자리들로 데려간다),
  `/rhythm`(한 박씩 두드려 마당이 다시 놓이는 것을 보여 준다).

### 논문은 쉬운 말로 설명한다

제목과 저자만 걸어 두면 "어려운 것에 기대고 있다"는 인상만 남고, 그 연구가 무슨 말을 하려는지는
아무에게도 전해지지 않는다. 그래서 논문에 기댄 페이지는 모두 네 줄을 갖는다.

- `config.ts`의 `PAPER.plain` — `problem`(연구자들이 걸렸던 것) · `work`(연구가 한 일) ·
  `took`(이 페이지가 가져온 것) · `left`(가져오지 않은 것), 각각 ko/en/ja.
- 규칙은 하나다. **열두 살이 읽어도 통하는 문장만 쓴다.** 전문 용어를 쓰면 설명이 아니라 인용이 된다.
- 화면은 `src/kit/paper`의 `PaperCard`가 그린다. 어느 페이지에서든 같은 자리에 같은 네 줄이 온다.
- `tests/modules/paper-plain.test.ts`가 모든 모듈의 `config.ts`를 훑어 네 줄이 세 언어로 있는지 본다.
  설명을 빠뜨린 채로는 새 논문 페이지를 추가할 수 없다.
가져오는 방식은 연구의 종류에 따라 다르다.

| 연구의 종류 | 페이지가 가져오는 것 | 예 |
| --- | --- | --- |
| 알고리즘·지표 | 방법 자체를 계산으로 옮긴다 | `/subtitle`, `/projection` |
| 질적 연구 | 방법이 아니라 **연구가 놓은 조건**을 화면에서 겪게 만든다 | `/beeper` |

질적 연구는 관찰과 인터뷰라서 코드로 옮길 수 없다. 대신 그 연구가 사람들을 놓아둔 자리를
다시 만들 수는 있다. 결론을 설명하는 대신 조건을 겪게 하면, 읽는 사람이 스스로 같은 것을 발견한다.

### `/rhythm` — 리듬으로 만나기

근거: **Birds of a Rhythm: The Effects of Haptic Pattern Similarity on People's Social Perceptions
in Virtual Reality** — Hyuckjin Jang, Jeongmi Lee (KAIST), ACM CHI 2025.

파는 기능(체험): **닮은 리듬이 가까이 온다는 것을 손으로 느끼게 한다.**

  봇을 붙였고, 그중 2명만 넉 주 안에 쓸 일을 만났다. 설계 공간을 그린 논문이면서 자기
  도구가 몇 번 쓰였는지를 숨기지 않고 적었다. 이 논문에서 가장 미더운 대목이라
  설계 공간보다 먼저 놓았다 — 공간을 먼저 펼치면 그저 또 하나의 표로 읽힌다.
- **여덟 축 가운데 넷은 가운데가 봉우리다.** 서버가 클수록 좋은 것도, 사이가 가까울수록
  좋은 것도, 다툼이 잦을수록 좋은 것도 아니다. 논문이 축마다 양 끝이 왜 어긋나는지
  따로 적어 두었다. 넷이라고 세어 앞에 내놓은 것은 이 페이지다.
- **점수를 만들지 않았다.** 질적 연구라 축에 눈금이 없다. 그래서 세 갈래 판정과 셈만
  있고 몇 점 같은 것은 없다. 저울을 만들면 논문에 없는 것을 세우는 일이 된다.
- **막는 자리가 하나 있다.** 신체 위협이나 금전 피해에서는 논문이 대화가 적절하지 않고
  플랫폼이나 법에 넘기라고 못박았다. 그 자리에 가면 나머지 셈을 지우고 그 말만 남긴다.
- 공동체의 갈래(사람 중심 / 스쳐 가는 / 거친 말이 규범인)는 눈금이 아니라 갈래라서
  축의 셈에 섞지 않는다. 시험이 그 분리를 붙들고 있다.
- 시험이 붙드는 것: 여덟 축 곱하기 다섯 자리 마흔 칸 전수, 봉우리 축은 판정이 좌우
  대칭이라는 것, 기운 축은 한 방향으로만 간다는 것, 안 맞는 까닭은 맞지 않는 자리에서만
  나온다는 것, 그리고 6 = 2 + 4 라는 깔때기의 덧셈.

**논문에서 가져온 것**: 5장의 기회 공간, 여덟 축과 양 끝과 어긋나는 까닭,
4.2절의 깔때기, 6.2절이 밝힌 빈자리(중간에 그만둔 사과가 무엇을 남기는지 모른다).

**가져오지 않은 것**: 숫자 전부, 표 1의 참가자 인적사항, 봇의 화면 그림.

**이 페이지가 더한 것**: 다섯 칸을 세 갈래에 붙이는 규칙, 봉우리 축을 넷이라고 세어
앞에 내놓은 것.

### `/space` — 안 보고 있는 칸

근거: **A Design Space for Intelligent and Interactive Writing Assistants** —
Mina Lee, Katy Ilonka Gero, John Joon Young Chung 외 33인, CHI 2024,
doi:10.1145/3613904.3642697. 전문은 arXiv:2403.14117v2, 분류표는 저자들이 공개한

파는 기능: **글쓰기 보조 도구를 다섯 갈래 서른아홉 차원에 놓아 보고, 비운 칸을
내가 안 정한 것과 학계 전체가 안 보는 것으로 갈라 준다.**

- **정본을 고르는 것이 이번 회차의 배움이다.** 논문의 표 1~7은 코드를 산문으로 풀어

  저자들이 따로 공개한 자료에는 코드가 목록 그대로 있어 그쪽을 정본으로 삼았다.
  다섯 갈래 서른아홉 차원 백아흔여섯 코드가 모두 여기서 왔다.
- **공간의 크기를 셌다. 논문은 세지 않았다.** 차원마다 하나씩 고르면 7.94×10^25(26자리),

  115편이라는 수가 크게 들리므로, 옆에 공간의 넓이를 놓아야 그 115편이 어느 만큼인지 보인다.
- **빈 칸을 두 종류로 갈랐다.** 내가 아직 정하지 않은 칸과, 5.2절에서 저자들이 이름을
  짚은 칸(audience, scalability, 생태계 여섯 차원)은 다른 종류의 빈 칸이다. 앞의 것은
  채우면 되고 뒤의 것은 채워 놓은 선례가 없다. 이 가르기는 논문에 없고 이 페이지가 더했다.
- **그림의 막대값은 하나도 가져오지 않았다.** 차원마다 논문이 몇 편인지는 그림 5에만
  실렸다. 그래서 화면에는 '적게 다뤄졌다'는 사실만 있고 편수는 없다.
- **차원과 코드의 이름을 옮기지 않았다.** 논문이 정한 말 그대로 두었다. 옮기면 논문에
  없는 말이 생긴다. 그 까닭을 화면에 적어 두었다.
- 시험이 붙드는 것: 갈래별 차원 수(5/8/10/10/6), 코드 총수 196, 두 자릿수(26과 58),
  아래끝을 갈래별로 나누어 곱해도 같은 값이 나오는 것, 그리고 5.2절이 이름을 짚은
  코드 여섯 개가 실제 분류표에 그대로 있는지.
- 첫 화면의 기본값은 요즘 흔한 대화형 글쓰기 도구 하나다. 과제·기술·상호작용은 차 있고
  사용자와 생태계는 통째로 비어 있다. 논문이 하려는 말이 첫 화면에서 이미 보여야 한다.

**논문에서 가져온 것**: 분류표 전부, 5.2절이 문장으로 짚은 것, 훑은 논문 115편과 저자 36명.

**가져오지 않은 것**: 그림 4와 그림 5의 막대값, 논문 115편의 개별 코딩.

**이 페이지가 더한 것**: 공간의 크기를 센 것, 빈 칸을 두 종류로 가른 것,
그리고 차원과 코드의 이름을 그대로 둔 것.

### `/nudge` — 기울기 직전의 저울

파는 기능: **급한 판에서 한마디를 할지 말지, 한다면 어느 통로로 할지를 값으로 따지고,
그 창이 몇 초 남았는지를 낸다.**

- 논문은 질적 연구다. 22명이 솔로 랭크를 하는 동안 곁에서 지켜보며 물었고 답을 주제로 묶었다.
  그러니 **숫자는 하나도 가져올 수 없다.** 가져온 것은 무엇이 무엇을 좌우하는가 하는 구조뿐이고,
  그 구조를 눈으로 보게 하려고 숫자를 붙였다. 화면에도 그렇게 적는다(8장의 원칙).
- 셈의 뼈대: `기대값 = 값(닿는 시각) × 닿을 확률 × 뜻의 또렷함 × 말의 무게
  − 손이 멈춘 값 − 나중의 위험`. 침묵이 언제나 0이므로 **0선이 곧 침묵**이고,
  어떤 통로가 0 아래로 내려가는 순간이 그 통로의 창이 닫히는 때다.
- '뜻의 또렷함'은 `fidelity − (1 − fidelity) × misreadCost`로 음수가 될 수 있다.
  이 항이 있어야 사람들이 굳이 타이핑하는 까닭이 설명된다. 잘못 읽힌 핑은 헛수고가 아니라
  팀원을 엉뚱한 곳으로 보낸다. 이 항이 없으면 어떤 상황에서도 핑이 이겨 화면이 심심해진다.
- 투표는 넷 중 셋이 응해야 하므로 이항분포 문턱을 넘어야 한다. 논문이 관찰한 대로
  거의 언제나 손해로 나온다 — 이것은 고칠 흠이 아니라 **논문의 발견이 셈에서 다시 나온 것**이다.
- 지고 있으면 말의 무게가 바닥값까지 준다. 그 결과 성적이 낮을 때는 거의 모든 상황에서
  침묵이 이긴다. 논문이 말한 '성적으로 생기는 서열'이 그대로 나온다.

**논문에서 가져온 것**: 여섯 가지 구조. 타이핑이 게임 시간을 먹는 것, 창을 놓치면 정보가
영영 나가지 못하는 것, 알아채지 못해 답하지 않는 것(참가자 아홉 명), 투표가 문턱을 넘지
못하는 것(관찰된 오브젝트 투표 중 세 표를 넘긴 것이 하나도 없었다), 지고 있으면 말의 무게가
줄어드는 것, 말이 오간다는 사실 자체가 앞으로의 위험으로 읽히는 것.

**가져오지 않은 것**: 숫자 전부와, 22명의 이야기와 인용.

### `/rulers` — 같은 것을 재는 다른 자들

근거: **Metric Design != Metric Behavior: Improving Metric Selection for the Unbiased

### `/checkup` — 비밀번호를 보여 주지 않고 확인하기

근거: **Understanding and Improving User Adoption and Security Awareness in Password Checkup
Services** — Sanghak Oh, Heewon Baek, Jun Ho Huh, Taeyoung Kim, Woojin Jeon, Ian Oakley(KAIST),
Hyoungshick Kim, CHI 2025, doi:10.1145/3706598.3713284.

파는 기능: **해시 앞 다섯 자만 보낼 때 서버가 알게 되는 것의 크기를 재고,
알려진 유출 단어에서 이 비밀번호에 이르는 가장 짧은 길을 찾는다.**

- SHA-1을 직접 구현한다(`src/core/checkup/sha1.ts`). `crypto.subtle`은 비동기라 한 자 칠 때마다
  즉시 답할 수 없고, 무엇보다 **비밀번호가 이 파일 밖으로 나가지 않는다는 것을 코드로 보일 수**
  있어야 한다. FIPS 180-2 검증 벡터로 시험한다.
- k-익명성: 앞 다섯 자 = 20비트, 남는 것 = 140비트. 같은 앞자리를 가진 해시의 기댓값은
  목록 크기 ÷ 2^20이다. 목록 크기는 서비스마다 다르므로 고정하지 않고 화면에서 움직인다.
- 변형 사슬: 사전 단어를 비밀번호에 **겹쳐 놓아** 본다. 겹쳐지는 자리가 있으면 남는 앞뒤가
  덧붙인 글자이고, 겹친 자리에서 어긋난 글자가 대문자화와 바꿔치기다.
  손질을 순서대로 벗기는 방식은 쓰지 않았다. `$unsh1ne2024!`의 맨 앞 `$`가 덧붙인 것인지
  `s`를 바꿔치기한 것인지 순서만으로는 가릴 수 없기 때문이다.
- 시도 번호 = 사전 순위 × 규칙마다의 가짓수. 이 수를 두 가지 추측 속도로 나눠 시간을 낸다.
  속도는 확정된 수치가 아니라 **가정**이고, 화면에도 그렇게 적는다.
- 사전에 닿지 않으면 '안전'이 아니라 **'알 수 없음'** 이라고 적는다. 여기 실린 단어는 백여 개뿐이다.

**논문에서 가져온 것**: 연구는 확인 서비스를 쓰지 않는 까닭으로 자기 효능감·경보 피로·
낮은 체감 급함을 꼽았다. 그래서 이 화면은 (1) "안전합니다"라고 말하는 대신 글자가 어디로 가는지
보이고, (2) 경고를 쌓지 않고 할 일을 **언제나 한 줄로만** 적고, (3) "유출됨" 딱지 대신
**몇 번째 시도에서 걸리는지**를 센다. 룩까지 같은 이유로 골랐다 — 붉은 기는 정말 급한 한 줄에만 쓴다.

**가져오지 않은 것**: 설문(n=238)과 사용자 연구(N=50)의 수치, 연구진이 실제로 시험한 화면,
그리고 진짜 유출 목록 조회. 이 페이지는 통신을 하지 않는다.

### `/chart` — 이 차트가 거짓말하는 크기

근거: **Automated Pipeline for Detecting and Analyzing Misleading Visual Elements** —
Minhyeong Kim 외 6인(서울대학교), IEEE PacificVis 2025.

파는 기능: **차트의 어느 요소가 자료를 몇 배로 어긋나게 보이는지 계산해 짚는다.**

- 뼈대는 하나다: **그림에서 읽히는 차이 ÷ 자료의 실제 차이**. 1이면 정직하다.

대신 왜곡의 크기를 어림이 아니라 계산으로 낸다.

### `/beeper` — 삐삐

근거: **Back to the 1990s, BeeperRedux!: Revisiting Retro Technology to Reflect Communication

파는 기능(체험): **하고 싶은 말을 숫자로 보내 보고, 그 말이 무엇이 되어 돌아오는지 본다.**

- **되돌아온 말**: 보내기를 누르면 상대의 액정에 숫자가 한 자리씩 찍히고(소리와 진동),
  그 사람이 그 숫자를 무엇으로 읽었는지가 돌아온다. 점수도 정답도 없다.
  '사랑해 빨리와'는 486이 되어 '사랑해'로 도착한다. 왕복에서 사라진 것이 곧 그 시절의 소통이다.
- 코드집은 낱말 목록이 아니라 **규칙이 있는 언어**로 보여 준다. 항목마다 어떤 방식으로 읽히는지를
  선언하고(`rule`), 화면은 그 방식별로 묶어 설명과 함께 낸다 — 소리로 읽기(가장 흔함), 수로 읽기(1004=천사),
  남의 말소리로 읽기(9=good), 모양으로 읽기(505), 뜻으로 읽기(9=행운).
  규칙을 알면 목록에 없는 숫자도 읽히고, 그것이 이 언어가 퍼진 방법이다.
  겹치기(8282, 0404)는 규칙 위에 얹히는 문법이라 표가 아니라 관찰 한 줄로 적는다.
- 코드집은 널리 알려진 것만 담았고, 지역·시기에 따라 달랐다는 사실을 화면에서 밝힌다.
- 오늘의 암호는 날짜에서 정해진다. 서버 없이 모두에게 같은 것이 보인다.
- 키패드는 실제로 눌리고 짧은 전자음이 난다(파일 없이 그 자리에서 파형을 만든다).

**논문과 다른 점**: 논문은 참여자에게 옛 기기를 쓰게 하고 관찰한 질적 연구다. 그 방법을 구현할
수는 없다. 이 페이지가 재현하는 것은 연구의 결론이 아니라 **조건** — 숫자만 보낼 수 있다는
제약 — 이며, 그 제약을 직접 겪게 한다.

### `/subtitle` — 자막 재분할

근거: **OptiSub: Optimizing Video Subtitle Presentation for Varied Display and Font Sizes via
Speech Pause-Driven Chunking** — Dawon Lee, Jongwoo Choi, Junyong Noh (KAIST), ACM CHI 2025.
<https://doi.org/10.1145/3706598.3714199>

파는 기능: **큰 글씨에서 화면 밖으로 넘치는 자막을, 말의 호흡을 지키며 다시 끊는다.**

- 글자 수가 아니라 **실제 표시 폭**으로 자른다. 캔버스로 지정한 서체·크기에서의 폭을 재며,
  측정기는 코어 밖에서 주입한다(코어는 브라우저를 모른다).
- 자를 자리는 점수로 고른다: 문장 끝 100 > 말이 쉰 자리 85 > 절 끝 70 > 괄호 닫힘 60 > 어절 사이 40 > 글자 사이 10.
  **이긴 근거는 덩어리에 남는다**(`Chunk.reason`). 상영관이 지금 자막에 대해 "왜 여기서 잘렸는지"를
  그 근거로 말하고, 고를 수 있었던 자리들을 점수 사다리(`BREAK_LADDER`)로 함께 보여 준다.
  설명할 수 없는 자동 편집은 결과를 믿기 어렵게 만들기 때문이다.
  쉼은 다음 말이 시작되는 자리와 그 직전 공백까지만 인정한다 — 한 글자라도 지나 자르면
  다음 말의 첫 글자가 앞 자막에 끌려온다.
- 표시 시간은 읽기 속도 상한(CPS)과 최소·최대 시간을 만족하도록 조정하되, 뒤로 밀지 않는다.
  한 번 밀면 어긋남이 끝까지 이어지기 때문이다.
- 품질 점검: 너무 빠름 / 너무 짧음 / 너무 김 / 폭 초과 / 시간 겹침.
  개수만 세지 않고 **무엇이 문제이고 어느 덩어리인지**까지 낸다 — 종류마다 뜻을 적고,
  해당 자막 번호와 실제 값(초당 글자 수, 시간, 넘친 폭)을 종류에 맞는 단위로 붙인다.
- 화면이 쓰는 숫자에는 **성격표**가 붙는다(`SETTING_ORIGINS`): 당신의 환경(글씨 크기·화면 폭) /
  실무 관행(줄 수·읽기 속도·표시 시간) / 이 화면이 고른 값(쉼 판정 기준).
  남의 자막을 다시 자르는 도구가 자기 숫자의 출처를 밝히지 않으면, 결과를 믿을 근거도 의심할 근거도 주지 못한다.
  관행에 해당하는 값은 한 곳이 정한 규격이 아니므로 출처를 하나로 못 박지 않는다.
- 쉼으로 본 자리가 몇 군데인지 상영관에 적고, **하나도 없으면 그 사실이 곧 한계 설명이 된다** —
  논문은 음성 파형에서 쉼을 찾지만 이 페이지는 자막 파일밖에 보지 못하므로,
  그런 파일에서는 자를 자리로 문장부호와 어절 사이만 남는다.
- **상영관**: 재생을 누르면 원본과 재분할본이 같은 시계 위에서 함께 흐른다.
  원본이 경계 밖으로 흘러나가는 장면이 이 페이지의 논거이므로, 두 화면은 위아래로 쌓아 폭을 지킨다
  (나란히 두면 화면 폭이 절반이 되어 자막이 접히고, 접힌 자막으로는 넘침을 판단할 수 없다).
  시간 막대에는 말이 쉰 자리를 함께 얹어 "왜 여기서 잘렸는가"를 보게 한다.
- 미리보기는 지정한 크기 그대로 그린다. 축소해 보여 주면 넘침 여부를 눈으로 판단할 수 없다.
- 예시 자막은 이 페이지가 다루는 문제가 첫 화면에서 모두 드러나도록 고른 날씨 예보다.
  1·2번은 0.1초 간격이라 한 묶음이 되고, 1번은 서른 자 남짓이라 그 쉼이 `MIN_FILL_RATIO` 뒤에 놓여
  분할 후보로 살아남는다(더 짧으면 쉼이 후보에서 빠지고 어절 사이가 이긴다). 어떤 자막을 예시로 두느냐가
  곧 무엇을 보여 주느냐이므로, 그 의도를 `config.ts` 주석에 남긴다.

- 결과 칸은 원본과 결과를 같은 자리에서 견준다 — 자막 수, 폭을 넘긴 자막 수, 가장 빠른 구간(상한과 함께).
  남은 넘침이 있으면 무엇을 바꿔야 하는지까지 적는다(글씨를 줄이거나 줄 수를 늘리기, 다만 한 줄에 담을 수 없는
  긴 낱말은 어느 쪽으로도 해결되지 않는다).
- **남의 파일을 고치는 도구**이므로 무엇이 남고 무엇이 사라지는지를 화면에서 밝힌다:
  남는 것(말의 순서·글자·시각), 다시 만드는 것(줄바꿈·SRT 번호), 버리는 것(WebVTT 큐 이름·위치 지정자·NOTE),
  그리고 `<i>` 같은 태그는 글자로 남아 **폭 계산에 그대로 들어간다**는 주의.
  이 네 가지는 해석기·생성기가 실제로 하는 일이며, 테스트로 고정해 두었다(약속과 동작이 갈라지면 도구가 아니라 거짓말이 된다).

**논문과 다른 점**: 논문은 영상의 음성에서 쉼을 찾지만, 이 페이지는 자막 파일만 입력으로 받으므로
자막 덩어리 사이의 빈 시간을 쉼으로 삼는다. 최적화 수식을 그대로 옮긴 구현이 아니다.

### `/projection` — 산점도 신뢰도 검사

근거: **Unveiling High-dimensional Backstage: A Survey for Reliable Visual Analytics with
Dimensionality Reduction** — Hyeon Jeon 외 8인(서울대학교 HCI Lab 주도), ACM CHI 2025, Article 394.
<https://doi.org/10.1145/3706598.3713551>

파는 기능: **차원 축소 산점도에서 가까워 보이는 것을 믿어도 되는지 확인시켜 준다.**

- 신뢰도(trustworthiness)와 연속성(continuity)을 함께 잰다. **하나만 보면 속는다.**
  지표마다 "무엇을 재는가" 옆에 **"무엇을 놓치는가"**를 같은 카드에 적는다. 재는 것만 적으면
  그 수치 하나로 판단하게 되고, 이 페이지가 하려는 말은 정반대이기 때문이다.
  화면에 적은 두 사례는 서로의 거울이며 둘 다 테스트로 고정돼 있다.
  - 모든 점을 한 자리에 **뭉치면** 연속성이 신뢰도보다 높게 나온다(붙여 놓은 잘못은 연속성이 세지 않는다).
  - 원 위의 점을 잘라 직선으로 **펴면** 새로 붙는 남이 없어 신뢰도는 0.9 위에 남지만,
    잘린 자리에서 이웃을 잃어 연속성만 내려간다(찢어 놓은 잘못은 신뢰도가 세지 않는다).
    같은 그림에서 거리 순위 상관은 0.8 아래로 떨어진다 — 국소가 멀쩡해도 전체는 어긋날 수 있다는 뜻이며,
    이것이 세 번째 지표를 따로 두는 이유다.
  - 이웃 적중률은 라벨이 옳다는 전제 위에 있다. 그 전제도 화면에 적는다.
- 이웃 적중률(라벨이 있을 때)과 거리 순위 상관(전체 구조)을 함께 낸다.
- 점마다 놓친 이웃·거짓 이웃을 세어 산점도에 색으로 얹는다.
- **진실의 렌즈**: 그림 위에 손을 올리면 그 자리에 렌즈가 켜진다. 렌즈 안에서는 그림이 말하는 거리 대신
  원래 자료의 사실이 색으로 나온다 — 원래도 이웃이던 점은 빛나고, 우연히 옆에 온 점은 붉어지며,
  밀려난 진짜 이웃에게는 실이 이어진다. 아래 판독 줄이 셋을 숫자로 센다.
  묻고 답하게 하지 않고, 손을 움직이는 동안 그림이 어디서 거짓말을 하는지 드러나게 한다.
- 값 옆에 그 값의 사정을 적는다: 어떤 이웃 수 k와 몇 개의 점으로 잰 값인지(`Metrics.k`, `pointCount`),
  그리고 **등급은 합격선이 아니라는 것**. 등급 구간은 `GRADE_THRESHOLDS`에서 그대로 그리고,
  가장 낮은 구간의 문턱(0)은 적지 않는다 — 0.00을 적으면 그것도 기준처럼 읽힌다.
  지표를 k 없이 인용하면 뜻이 흐려진다는 사실을 화면이 직접 말한다.
- 예시 자료를 보고 있을 때만 그 예시가 무엇을 보여 주려는 것인지 밝힌다(가까운 두 덩어리가 PCA에서 겹친다).
  남의 자료에 대고 같은 설명을 띄우면 그 자료가 그런 자료라는 뜻이 되어 버리기 때문이다.
- 좌표 열을 지정하면 사용자의 t-SNE·UMAP 결과를 검사하고, 지정하지 않으면 PCA로 기준선을 만든다.
  PCA는 난수를 쓰지 않아 같은 자료에서 항상 같은 그림이 나온다.
- 점 개수의 제곱만큼 비용이 들므로 상한(1200점)을 두고, 넘으면 화면이 잘라 쓴 사실을 알린다.

**논문과 다른 점**: 서베이는 신뢰성 문제의 분류 체계와 워크플로 모델을 제시한다. 이 페이지는 그중
널리 쓰이는 왜곡 지표를 직접 계산해 보여 줄 뿐, 서베이의 분류 체계를 구현한 것이 아니다.
지표의 정의는 Venna와 Kaski가 세운 표준 정의를 따른다.

### `/` — 개인정보 지우개

파는 기능: **문서를 남에게 보내기 전에 개인정보를 찾아 가린다.**

- 이메일·전화·주민등록번호·사업자등록번호·카드번호·여권·IP·API 키·좌표 탐지
- 주민등록번호·사업자등록번호·카드번호는 **검증 자리(체크섬)까지 확인**한다.
  정규식만 쓰면 "숫자 13자리"를 전부 잡아 오탐이 쏟아진다.
- 가리는 방식 4종: 전부 / 일부만 / 유형 / 가명(같은 값에 같은 번호 → 문서의 관계 보존)
- 원문은 컴포넌트 상태에만 있다. URL·저장소·서버 어디에도 남기지 않는다.
  "브라우저를 떠나지 않는다"가 이 페이지의 기능 자체이므로, 그 약속을 어길 경로를 만들지 않았다.
- 가장 민감한 주민등록번호는 '일부만' 방식에서도 아무것도 남기지 않는다(앞 6자리가 곧 생년월일).

이 도구를 루트에 둔 이유: 처음 온 사람이 설명 없이 쓸모를 알 수 있고,
"왜 챗봇에 묻지 않고 여기서 하느냐"에 대한 답이 기능 안에 이미 들어 있다.
챗봇에 붙여넣으면 안 되는 내용을 다루는 도구이기 때문이다.

### `/color` — Chroma Lab

파는 기능: **시드 색 하나로 접근성 검증까지 끝난 색 체계를 뽑아낸다.**

- OKLCH 기반 톤 램프 11단계 × 조화 트랙(단색·유사·보색·분할보색·삼색·사색)
- WCAG 2.1 대비비와 APCA Lc 동시 표시, 배경별 통과 단계 목록, 3단계 크기 미리보기
- 색각 이상 4종 시뮬레이션(중증도 조절), 유병률 표시
- CSS / SCSS / JSON / Tailwind / SVG 내보내기, 접두사 지정
- 팔레트 이름 짓기(로컬 LLM 선택, 없으면 규칙 기반)
- 모든 상태가 URL 질의문자열에 실려 링크로 공유된다

루트가 아니라 2층에 있는 이유: 색 대비 검증은 제품을 출시하는 사람에게 필요한 도구지
지나가는 방문자를 붙잡는 도구가 아니다. 필요한 사람이 찾아오는 자리에 둔다.

특성 표와 특성 총개수, 노드의 깊이·경로·판매 기능 문구는 화면에 노출하지 않는다.
사용자에게는 제목·설명·도구·의견란만 보인다.
